# Faster R-CNN 与 YOLO11 初步比较及改进方向

时间：2026-10-29，北京时间。YOLO已完成24轮训练，并用已保存best权重、batch=1成功补跑三个评估集，无重训。RT-DETR仍在训练，最终队列还会用batch=4核对现代模型评估。以下为当前已完成的统计，不是最终架构选型结论。

机器可读本地数据：`records/remote_runs/20261029_tooth1/faster_yolo_comparison.json`。历史53类基准来自既有candidate_recall.json。

## 口径与限制

所有下表是原图坐标、一对一、忽略类别的框匹配，score≥0.01；多生牙身份只来自评估GT，不参与单类训练。IoU≥0.5表示较宽松框覆盖，IoU≥0.75表示严格定位，均不代表解剖中心点或临床识别正确。

新旧Faster R-CNN使用最后一轮；YOLO使用验证集best。两架构的初始化、输入几何、优化器、batch及后处理不同，所以结论针对当前完整配方，不是纯架构因果结论。不同模型分数未校准，同阈值不等价于相同召回工作点。

## 优先改进方向

### P0：先查漏检发生在哪里，暂不叠加新loss

对验证集每个遗漏牙齿，区分：低分被阈值过滤、重叠被NMS抑制、已有框但IoU不达标、原始候选中根本没有合适框。需要保留受控的pre-NMS候选与对应分数。当前已有导出只能描述后处理结果，不能断言遗漏原因。

仅用val对比conf=0.001/0.005/0.01/0.05与NMS IoU=0.6/0.75/0.85，记录候选上限和截断状态，固定候选数量/未匹配候选负担下比较召回。不使用外部集选择阈值，不强制固定牙齿总数。若放宽后处理已经找回牙齿，无需先改模型。

### P1：定位和重叠牙保护

YOLO在怀柔40颗多生牙满足IoU≥0.5，但仅29颗满足IoU≥0.75：其中11颗属于能框到但不够准；另13颗未满足宽松定位标准，未必全部属于完全无候选。

先在val复核高误差框、密集重叠乳恒牙和多生牙，保持全牙框语义一致。随后做同YOLO配方960→1280分辨率对照、受控重叠后处理对照，避免同时换损失、采样与分辨率。没有真实牙冠标注前，不把固定方向权重当作牙冠监督。

### P2：证据支持时再提高稀有形态学习

若遗漏在低阈值pre-NMS仍不存在，再考虑训练集中含多生牙/强重叠病例的温和采样、局部高分辨率训练与全图上下文的配合。原始extra标签可作为训练病例采样元数据，但预测目标仍仅为tooth。必须控制增强是否造成框被裁断或漏标，不直接恢复多生牙身份分类头，不预设RFS有效。

### P3：接口以轻量分层为主

YOLO目前每图约43–45个框，已接近标注牙齿数量；不能继续把“减少到固定框数”作为目标。优先保留每实体一主框、局部/上下文图、复核入口及原始证据。只有诊断确认重复仍造成明显负担，才增加学习型同牙归并，避免复杂化。

## 暂定决策

保留单类检测+后端编号主线；YOLO11m作为优先继续验证的轻量候选，Faster R-CNN保留对照，等待RT-DETR完成后再收敛。短期顺序为遗漏归因 -> 验证集后处理/候选预算曲线 -> 定位与分辨率对照 -> 有证据时做采样或监督改造。暂不增加FDI头、LLM调用或多模型融合。
