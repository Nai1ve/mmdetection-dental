# 单类牙齿定位与后端编号：当前主设计

状态：设计定稿候选，未经单类训练验证；GPU不可用，本轮不训练。

本设计更新此前“存在性+FDI辅助头”的主线：第一阶段只承担牙齿实体定位，FDI辅助头降为可选消融，不是必须实现的模块。此前53类YOLO11/RT-DETR训练脚本仍是架构对照工具，不自动代表本设计，也不应未经修改作为单类主线启动。

## 1. 目标与任务边界

流程：原图 -> 单类Tooth检测 -> 可逆候选整理 -> 结构化证据接口 -> 后端视觉编号与复核。

第一阶段输出真实牙齿的候选框、检测分数及可追溯视觉证据。不输出最终FDI，不将“有牙但编号不确定”作为删除依据；不判断病理性缺牙，不把高密度影或未知形态直接认定为牙齿。

所有已标注乳牙、恒牙、牙胚、埋伏/异位牙及多生牙的有效牙齿实例合并为Tooth；类别转换不新增未标注对象，也不改变框的边界定义。超出既有标注覆盖范围的对象不宣称已受监督。

多生牙在训练中与其他牙齿一样是Tooth；原始extra_tooth标签在评估侧保留，以计算其框覆盖，但绝不作为推理接口的真值属性。多生牙实体框召回与后端多生牙身份识别分别考核。

成功定义：在可接受候选数量下提高全牙及多生牙框召回和定位质量，同时降低重复实例；不是靠输出更多框获得更高召回，也不是固定输出正常牙列数量。

## 2. 检测模型

### 2.1 最小可行主模型

先保留Faster R-CNN R50-FPN，改成单类Tooth分类及一套bbox回归。共享backbone/FPN、RPN、RoI特征，仍是一个检测模型，不串联第二个检测器，不做模型融合。

训练目标为标准RPN损失、RoI牙齿/背景分类损失和bbox回归损失之和。标准单类bbox分支天然仅需一套前景回归参数；不把更换自定义loss作为首轮必需项，不加入CCSW，不新增FDI身份分支。

先验证最小设计，再决定是否增加独立的定位质量预测或同牙关系学习，避免一开始无法归因。检测分数初始只是模型分数，未经校准不得写作临床存在概率。

### 2.2 定位对象

沿用人工全牙框，包括现有标注中被吸收牙根、牙胚等实际边界；不能一边改成牙冠框一边继续用全牙框指标比较。框中心只是派生几何量，不等同于牙冠中心、萌出点或解剖中心。

冠部辅助监督需另有可靠标注或单独验证的伪标签方案，目前不进入主模型。不能把上下颌固定方向规则强制施加于所有异位牙及多生牙。

### 2.3 后处理与证据池

区分内部原始候选池、后处理后候选和接口代表框。阈值、NMS及候选上限仅在val上确定；记录各阶段召回损失。保留适度宽松的原始池用于追溯，但不能宣称低于导出阈值或已被RPN丢弃的牙仍可恢复。

单类NMS可能抑制真实重叠牙，必须对乳牙/恒牙胚重叠、多生牙邻接案例专项复核。先比较标准NMS与宽松NMS，不默认增加更多复杂后处理有效。模型所有原始候选仍受计算与存储上限约束；发生截断应输出标记。

YOLO11m和Ultralytics RT-DETR-L后续也训练单类版本作为架构对照。初始化、分辨率、训练预算和后处理差异如实记录；原先“YOLO或RT-DETR必然提高多生牙召回”的说法不成立。

## 3. 实体整理：可逆而不是直接删框

输入为原图坐标框、模型分数、可选视觉描述及来源ID。输出是暂定实体组，不将几何重叠直接当作同一物理牙齿的确定证据。

第一版采用高重叠的保守分组：最高分候选作为主框，其余框作为坐标备选保留，不做未经验证的坐标平均。不采用链式传递归并，防止A近B、B近C最终把不同牙齿串在一起。分组策略对正常牙和多生牙统一，不使用测试集身份。

当前几何验证的IoU=0.85仅是候选原型值，不是部署定值。既有三中心基线怀柔测试从86.3框/图降到72.0组/图，多生牙保持44/53；不能由此推断单类模型会有相同效果。

后续若纯几何归并不足，再学习同牙关系：训练GT匹配唯一明确的候选对，同一GT为同牙、不同GT为异牙，模糊匹配忽略。负样本必须覆盖乳牙与恒牙胚、贴邻牙和多生牙；外部测试不参与配对训练。接口先保留可逆性，不能未经验证硬删除。

## 4. 后端接口

### 4.1 三层证据

1. **主实体层**：默认显示较可靠的实体主框，供全局编号。主实体也不是已确认诊断。
2. **待复核层**：独立低分组、坐标分歧组及重叠关系不明确组，保留摘要和按需图像访问入口。低分不等于多生牙，不等于无需处理。
3. **原始证据层**：候选框、来源、备选坐标、可选视觉向量及处理轨迹，供回溯。不是把全部原始框一次塞入LLM提示词。

后台始终可访问全部待复核索引；默认展示预算仅影响分页，不永久截断证据。输出review_total、review_returned与has_more，防止“没有展示”被误读为“没有候选”。不强制牙齿总数，不根据FDI缺位自动补框。

### 4.2 病例级字段

schema_version、case_id、image_ref、width、height、原图坐标约定、模型/权重版本、阈值与分组策略、候选截断状态、主/复核实体数量。方向信息必须标注来源与是否已确认；不能从普通图片读取顺序擅自断定患者左右。

### 4.3 实体级字段

- entity_id：稳定的病例内索引，与FDI解耦。
- bbox_xyxy：原图像素坐标，明确左上/右下约定；bbox_center和归一化坐标可派生。
- detection_score：非临床校准概率；有定位质量预测时另列quality_score，不能拿分类分数冒充定位质量。
- layer与status：primary/review，以及provisional/unresolved等状态。
- crop_ref与context_crop_ref：本牙局部图与带邻牙上下文的裁剪；保留全景图链接与坐标映射。
- source_candidate_ids、alternative_boxes、feature_ref：可追溯原始证据。新检测器不具备视觉特征导出时feature_ref允许为空，不伪造1024维特征。
- relations：重叠、距离、相邻候选等几何关系，明确只是软线索，不能把牙弓拟合偏离或恒牙中心非线性当作删框条件。

FDI、乳恒牙身份、是否多生牙不属于主检测接口的必需字段。后续可用53类基线提供可选身份先验消融，但不进入主方案的保留逻辑。

### 4.4 示例

```json
{
  "entity_id": "e017",
  "bbox_xyxy": [420, 260, 468, 355],
  "detection_score": 0.16,
  "layer": "review",
  "status": "provisional",
  "crop_ref": "case_local/e017/tooth",
  "context_crop_ref": "case_local/e017/context",
  "source_candidate_ids": [71, 94],
  "alternative_boxes": [[422, 259, 470, 353]],
  "feature_ref": null,
  "fdi": null
}
```

示例值仅表示字段结构。裁剪不上传公共图床，接口使用受控本地或私有资源引用，需脱敏与访问控制。

## 5. 后端编号职责与边界

后端必须是能看图的模型或有图像查看工具的Agent，不能只靠坐标排序。先看全景和主实体，结合局部及上下文，必要时查看复核层、替代框及重叠关系；无须在本轮接入任何LLM API。

编号结果须引用entity_id及证据；允许unresolved、疑似额外牙和要求人工复核。实体编号、合并/拆分建议与原检测证据分开保存，不能覆盖原始框。FDI解码中的唯一性等约束可提供检查信号，不能为了满足约束强行删除候选或凭空增加牙齿。

若最终没有调用完review层，报告必须注明未完成复核，不能把主层数量当作全口牙数。未检出的实体无法通过接口自行恢复；需要额外局部重检能力时应另立实验，而不宣称本接口已经具备。

缺牙判断后置：现有qy名称仅表征病例分组，不能代替确认的缺失牙位与病理原因标签。需要年龄、替牙阶段、病史与医生复核，不能单凭“未检测到某FDI”诊断病理性缺牙。

## 6. 实验顺序

| 编号 | 检测模型 | 接口/身份信息 | 目的 |
|---|---|---|---|
| E0 | 已有53类Faster R-CNN | 原始候选 | 历史基准，可复用 |
| E1 | 单类Faster R-CNN | 原始候选 | 隔离标签合并影响 |
| E2 | E1同一权重 | 保守可逆分组 | 隔离接口影响，不重新训练 |
| E3 | 单类YOLO11m | 与E1相同评价接口 | 架构/配方对照 |
| E4 | 单类RT-DETR-L | 与E1相同评价接口 | 架构/配方对照 |
| E5 | 最佳验证集方案 | 学习型同牙关系 | 验证额外复杂度是否必要 |
| E6 | 选定检测器 | 无FDI先验 vs 可选FDI先验 | 后续验证后端是否真能从先验受益 |

E1和E0优先保持原输入、初始化、优化器、24轮和seed一致，先用batch=2保证任务定义对照；资源优化batch=4/6放在后续成对实验中，不能与类别改变混作唯一差异。E3/E4需要修改当前只支持53类的训练与评估脚本，另存单类配置。单类AP与53类mAP不可直接作数值胜负比较，应比较类无关框指标。原extra_tooth标签仅用于分组评估，不回流单类分类头。

首选private_only三中心开发划分，验证集选择阈值、分组和checkpoint，再固定到内部/外部测试。北京口腔单中心划分用于后续跨中心复核，不合并两种划分的重复样本计数。外部集已被反复分析，需要如实披露，并争取新增独立确认集。

## 7. 评价与验收

- **找全**：全牙与多生牙框召回，IoU≥0.5和0.75；总是同时报告匹配数/真值数，不只报告百分比。
- **框准**：IoU分布、按GT尺度归一化的框中心误差、严格IoU命中。派生中心指标不冒充解剖标志点准确率。
- **少冗余**：每图框/组数及P50/P95/最大值、未匹配候选、每个GT对应的重复候选数。
- **接口保真**：代表框召回损失、异牙误合并、不同牙齿在一个组内的冲突、复核组负担及原始证据可恢复性。多生牙与重叠乳恒牙单独分析。
- **可比工作点**：固定候选预算或固定未匹配候选水平下比较召回，并展示完整权衡，不用“阈值更低/框更多”冒充改进。
- **后端效果**：未来再评估编号正确率、病例级多生牙识别、未决比例和复核次数。接口条目减少本身不证明编号变准。

不预设95%或99%作为已实现目标。验证集多生牙样本少，优先看绝对遗漏及案例复核，再对有效设计补多种子与按图像聚类的不确定性估计；没有患者ID时不宣称患者级独立。新模块只有在验证集的候选负担下降且召回/定位损失可接受时才进入主线；临床可接受边界应与医生确定，未确定前不声称达到临床可用。
