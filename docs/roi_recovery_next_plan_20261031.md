# ROI 补漏下一轮代码与实验计划

## 本地复核结论

使用上一轮 multi_val_.25 的完整 164 张真实候选，执行 audit_roi_recovery.py：同 ROI 输出框两两组合中 IoU≥0.85 的比例为 99.7319%。这是阈值筛选后输出的统计，不代表训练所有槽位的完整激活率，但提示严重的重复预测，不能将四槽输出解释为四颗独立牙齿。

保留全部原始 YOLO 框、只合并新增备选，新增预算分别 0/8/16/32：

| 新增预算 | 每图候选均值 | 全牙命中@0.5 / @0.75 | 多生牙命中@0.5 / @0.75 |
| --- | ---: | --- | --- |
| 0 | 49.1829 | 6896 / 6587 | 7 / 7 |
| 8、16、32 | 49.2866 | 6896 / 6587 | 7 / 7 |

这解决了代表替换导致的基线退化，但没有保住新增召回。不能声称接口改进已经提升检测。实际新增框的高重叠、低区分评分，比单纯延长训练更值得优先诊断。预算是“最多新增”，不是总框数固定；原始框超过预算不删除。

原始审计保存在本地 records/remote_runs/20261031_roi_pilot/protected_interface_audit，未上传患者级候选。GT 最大 IoU 字段仅是逐牙覆盖诊断，不替代一对一召回评估。

## 已准备代码

- dental_roi_head.py：可配置 ROI 7x7 / 14x14；可选已有预测框条件编码；可选质量与新增实例评分。默认结构保持旧 checkpoint 兼容。
- run_dental_roi.py：缓存分辨率入 manifest；训练结构选项入 checkpoint；推理严格检查缓存分辨率。新增候选保存 roi_id、slot_id、来源及辅助分数。
- 已有框条件：每 ROI 选附近最多 8 个预测框，相对坐标和检测分数编码后聚合，不读取 GT；训练/推理使用相同逻辑。
- 质量监督：Hungarian 匹配预测与 GT 的 detached IoU；新增监督：匹配 GT 是否尚未被分数≥0.05 的原始框以 IoU≥0.75 覆盖。未匹配槽监督为零，partial GT 仍按原规则忽略不确定负例。
- 此处“新增”是检测覆盖定义，不是临床多生牙身份。所有完整 GT 继续参与框回归，没有硬屏蔽正常牙或只训练多生牙。
- audit_roi_recovery.py：逐 GT 覆盖诊断、槽位计数、同 ROI 重复率，以及保留原始框的可逆候选整理。全部新增候选由原 candidates.json 保留，interface.json 引用分组和延后成员，不删除原始信息。
- 辅助分支候选可按 objectness×quality×novelty 排序；这是待验证排序启发式，不宣称校准概率。原始分数未被替换，常规 raw 指标仍用 objectness。

## 待上机矩阵

run_roi_recovery_matrix.sh 串行运行，冻结同一 YOLO checkpoint，seed42、6轮、AdamW 1e-4、每图最多12个训练 ROI，均四槽：

| 名称 | ROI | 已有框条件 | 质量/新增评分 |
| --- | --- | --- | --- |
| control7 | 7x7 | 无 | 无 |
| resolution14 | 14x14 | 无 | 无 |
| conditioned7 | 7x7 | 有 | 无 |
| quality7 | 7x7 | 无 | 有 |
| combined14 | 14x14 | 有 | 有 |

每组验证头阈值 0.25/0.5，均评估完整 val，并执行候选预算审计。质量与新增评分当前作为一组辅助任务消融；若有效，再拆开两分支，不能直接归因于其中任一分支。组合不能单独证明交互效应。

只保存各组末轮 last.pt。7/14 两种缓存各保存 train/val，14x14 特征体积约为7x7的四倍；上机先核对磁盘和至少两张真实图的 GPU 烟雾测试，再启动完整矩阵。不要下载特征缓存。

启动前设置 PYTHON、DATA_ROOT、DETECTOR、全新 RUN_ROOT，进入仓库后使用 setsid/nohup 脱离会话执行 bash tools/run_roi_recovery_matrix.sh，外部 launcher.log 放数据盘。runner.pid 是脚本实际控制器 PID，状态按最后事件判断。脚本默认不关机、不追加任务；失败保留日志，不覆盖目录重跑。

## 验证与后续门槛

本地已通过原始头回归测试、14x14 条件头与辅助分支有限梯度、空目标/partial/overflow 测试、保存加载、两轮合成缓存优化，以及真实完整 val 接口审计。shell 通过 bash -n。尚未完成新结构的真实 GPU 训练与完整远端矩阵。

先观察槽位重复率、逐槽命中、原有框保护以及同候选负担下多生牙 R@0.5/0.75。若仍大量重复，先核对完整多 GT ROI 的分布、匹配分配与空槽梯度，不直接添加排斥损失：真实重叠牙不能被硬性互斥。当前条件编码是轻量先导，尚非完整的跨实例关系网络。

6轮单种子只用于筛查；候选方案确定后再增加种子、确认收敛，并做完整内部/外部测试。外部集不参与方案或阈值选择。数据 GT、划分、FDI 标签均无需调整。
