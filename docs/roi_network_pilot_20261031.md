# ROI多实例复查网络与数据安排

## 数据需要调整吗

原图、FDI53/Tooth1标注与现有划分不变，不重新分配病例，不新增多生牙类别。新增的是派生的ROI特征缓存和区域内GT，不是新的独立病例数据集。

训练缓存只来自train，验证缓存只来自val；内部/外部暂不生成。数据盘保存缓存、权重和日志，源码库不保存特征缓存。文件SHA256绑定原检测器和标注版本。

候选ROI完全由固定YOLO预测产生（score>=0.05、最多64个种子、每框扩大1.6倍）；不使用GT指定漏牙位置。训练时只有完全落入ROI（覆盖比例>=0.9999）的牙作为完整GT；部分可见牙只用于屏蔽有歧义的负样本。超过4颗完整GT的ROI两种模型均跳过，记录overflow，不把遗漏GT当背景。当前未人工确认的9对乳恒牙标注不自动去重。

## 网络

冻结原始YOLO11m，复用P3/P4特征；ROIAlign为7x7，拼接后1x1投影128维；49个位置token，2层、4头交叉注意力解码器；输出牙齿存在性和ROI内xyxy坐标。归一化ROI坐标通过线性映射加入，是软位置特征，不是牙弓或FDI硬规则。

- single：1个query槽，监督与种子框最相关的一颗完整牙，用作局部单实例精修对照。
- multi：4个query槽，监督区域内全部完整牙，通过Hungarian集合匹配学习多个实例。
- 两者使用相同缓存/ROI列表和最大容量4的可训练区域；但single只监督主实例、multi监督全部实例，这属于任务能力差异，不能声称两者正样本监督量完全相同。
- 原YOLO权重完全不更新，无共享方向模块、邻牙排斥损失、第二个完整检测器、LLM或新冠根标注。

损失为匹配后的5倍L1+2倍GIoU+存在性BCE，未匹配槽背景权重0.25；部分可见牙与未匹配槽IoU>=0.5时忽略该负样本。没有强制牙齿互不重叠。

## 首轮先导

seed42，原始baseline_s42 best.pt，缓存train/val全部图像。头使用AdamW lr1e-4、weight_decay0.01，6轮，每图随机最多12个可训练ROI，梯度裁剪1；最终轮last.pt固定用于评价，不按测试集或中途人工挑权重。

single与multi分别在val评估头分数0.25和0.5。原始全图框与分数保留，头框追加并保留ROI来源；分别报告全集和可逆分组的类无关R@0.5/0.75、多生牙匹配及候选负担。增加候选集合带来的全牙最大匹配召回不下降不是成功证据，要比较同负担下的有效找回。

缓存清单报告完整GT覆盖率、overflow、无可训练ROI情况。没有任何YOLO候选的区域无法由此head凭空发现；这是当前ROI机制的覆盖上限。ROI输出裁到区域内，因此不能精修伸出ROI的完整牙；本轮只作为局部复查可行性先导。

缓存float16，训练头float32。预期数GB缓存，按实际生成量监控；只保留最终覆盖更新的last.pt，不每轮另存大权重。本版先验证单GPU，无resume/DDP承诺。

## 软件测试

`tools/check_dental_roi.py`：单/多实例前后向、空GT、溢出屏蔽、部分牙处理、ROIAlign、集合顺序不变性、保存加载、合成缓存真实优化器循环通过。软件正确性不代表真实召回改进。

`tools/run_dental_roi.py`分cache/train/eval三个入口。`tools/run_roi_pilot.sh`串行生成缓存、训练两个头、评估阈值；RUN/runner.pid记录真实控制器，status.csv追加状态，失败停止，不自动改超参，不自动关机。
